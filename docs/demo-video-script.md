# v1.0 Demo Video Script and Storyboard

Target runtime: approximately 3 minutes 20 seconds. Use only the synthetic public demo after completing the recording checklist.

## 0:00–0:12 — Title and disclosure

**Picture:** Product title, then the Home page.

**Narration:** “This is the Enterprise AI Knowledge & Action Agent, a publicly deployed engineering prototype built around one rule: AI can prepare enterprise work, while deterministic systems retain authority over business mutation. Every identity and business record shown is synthetic.”

## 0:12–0:30 — Employee tasks first

**Picture:** Home page; point to Request annual leave, current balance, recent requests, and Assistant as a secondary capability.

**Narration:** “It is an employee portal rather than a chatbot shell. Common tasks, current state, and governed sources lead the experience. The assistant is embedded where language helps.”

## 0:30–1:00 — Governed knowledge

**Picture:** Open Assistant, ask the guided carry-over question, open its citation in Policy Library.

**Narration:** “A policy answer starts with server-resolved employee context. Approved, effective, applicable documents are filtered before vector ranking. Retrieved text is treated as untrusted evidence, while the server builds a citation to the exact governed document version and section.”

## 1:00–2:20 — Annual Leave authority boundary

**Picture:** Prepare next Friday. Show the persisted draft card. Type “yes, submit it” and show that chat does not execute. Open Review. Compare dates, hours, and projected balance. Begin authorization, acknowledge the exact draft, submit, then show success, updated balance, and audit evidence.

**Narration:** “The model has READ and PREPARE tools only. Preparation persists the authoritative draft; the browser does not reconstruct it. Conversational confirmation is deliberately non-authoritative. On the separate Review surface, a short-lived challenge binds explicit consent to this exact revision. A private worker locks, revalidates, and commits the leave record, final state, and audit evidence in one PostgreSQL transaction.”

## 2:20–2:45 — IT Support revision model

**Picture:** Open an existing prepared IT request. Show the four persisted fields, edit the summary, save a new revision, and show that a fresh authorization is required. Use an existing completed ticket for result/history; do not perform a second destructive execution.

**Narration:** “IT Support reuses the control-plane safeguards without hiding domain rules in a generic workflow engine. Edits create immutable revisions, and authorization always binds to the current revision. Exactly-one ticket creation is protected by a unique source-action link.”

## 2:45–3:05 — Alex and Sam isolation

**Picture:** Show Alex’s requests, switch to Sam, show different balance and owned records.

**Narration:** “The browser selects a fixed synthetic persona, but employee authority is resolved on the server. Owner-scoped reads prevent Alex and Sam from seeing each other’s action or ticket details.”

## 3:05–3:20 — Architecture and close

**Picture:** About page and architecture documentation. Show the source link only if anonymous repository access has been verified after publication. End on the v1.0 release page if it exists.

**Narration:** “The public portal fronts a private FastAPI service, PostgreSQL with pgvector, and a dedicated action worker. The result is production-minded rather than production-ready: synthetic systems, explicit limitations, and evidence-backed trust boundaries.”

## Recording checklist

- Run the private reset first and wait for maintenance to clear.
- Use synthetic data only; never enter visitor, customer, employer, password, or confidential information.
- Confirm public readiness reports database, migration, corpus, and worker healthy.
- Record the exact deployed source commit and, after release, the exact `v1.0.0` tag.
- Confirm the governed baseline is 13 documents / 47 chunks.
- Confirm provider quota and timeout availability before recording the two provider-backed requests.
- Disclose that Gemini availability and public-demo quotas can limit Assistant requests.
- Confirm the repository is anonymously accessible before showing a source link.
- Check the browser console and capture at a clean desktop viewport.
- Do not fabricate or publish a video URL before a real video is uploaded and reviewed.
